Getting started

A ten-minute tour: start GitBench, sign in with a demo account, create a project, push a repository, file an issue and run your first CI pipeline.

Prerequisites

You needFor
The .NET 10 SDKRunning from source (dotnet run)
git on the server's PATHGit over HTTP, code search and source archives. Without it the Git endpoints answer 503
Docker (Engine or Desktop)Running the container image, and running CI pipelines (every CI job runs in a container)
A modern browserThe web interface (Blazor Interactive Server, so it needs WebSockets)

You do not need a separate database server: GitBench uses SQLite by default. PostgreSQL is optional, see Postgres or SQLite.

Option A: run from source

From the repository root:

dotnet run --launch-profile http

Then open http://localhost:5108. On the first start GitBench creates gitbench.db (SQLite), applies all migrations and, because the http launch profile uses the Development environment, fills the empty database with demo users, projects and issues. The Git SSH server is also on in Development, on port 2222.

To reset a development install, stop the app and delete gitbench.db* and the repos/ folder. The next start seeds everything again.

Option B: run with Docker

docker compose up -d --build
docker compose logs -f gitbench

This builds the image and listens on http://127.0.0.1:8080. The image runs in Production mode, which changes three things for a first try:

  • No demo data. Seed__DemoData=false, so there are no demo accounts. Register your own at /account/register.
  • Secure cookies. Sign-in cookies are marked Secure and will not work over plain HTTP. For a quick local trial add Security__SecureCookies: "false" under environment in docker-compose.yml. For anything real, put a TLS proxy in front (see Reverse proxy).
  • CI is off. Ci__Enabled=false because the container has no Docker daemon. See CI in the container.

To make yourself a site admin, register, then restart once with Bootstrap__AdminUsers set to your username (uncomment the line in docker-compose.yml).

The rest of this tour assumes Option A. With Docker, replace http://localhost:5108 with your address and sign in with the account you registered.

1. Sign in with a demo account

Open /account/login. The seed data creates four accounts, all with the same password, which is defined in SeedData.DemoPassword in Data/SeedData.cs. You can sign in with a username or an email address.

UsernameRole on the demo data
aliceSite admin, Owner of the demo projects
bobDeveloper on WEB
carolMaintainer on WEB, Developer on OPS
danDeveloper on WEB, Maintainer on OPS

Sign in as alice for the tour so you can see the admin pages too. Five failed attempts lock an account for five minutes. The demo password is public, so never enable demo data on a server other people can reach.

2. Create a project

  1. Open /projects/new (the New project button).
  2. Pick a key: 2 to 10 capital letters or digits, starting with a letter, for example DEMO. Issues will be numbered DEMO-1, DEMO-2 and so on. Keys are unique across the whole site.
  3. Give it a name and choose visibility: Private (members only) or Internal (every signed-in user can see it as a Viewer).
  4. Save. You become the project's Owner. Manage members at /p/DEMO/members and settings at /p/DEMO/settings.

A project can optionally live inside a group; pick the group on the same form. More in Concepts.

3. Create a repository and push over HTTP

  1. Open /p/DEMO/repos and create a repository, for example with the name hello. It becomes a bare Git repository on the server.
  2. On your machine, create something to push and push it. Git asks for your username and password; enter your GitBench username and the password (or a personal access token, see below). 
    mkdir hello && cd hello
git init -b main
echo "# Hello" > README.md
git add . && git commit -m "First commit"
git remote add origin http://localhost:5108/git/DEMO/hello.git
git push -u origin main
  3. Refresh /p/DEMO/repos/hello. Your files, commits and branches are there.

Instead of a password you can use a personal access token: create one at /account/profile under Access tokens, give it the write_repository scope, and paste it where git asks for the password. It is shown once. Use a credential helper (git config credential.helper osxkeychain, manager or store) so you are not asked every time.

Pushing needs the Developer role or higher. A Viewer gets 403. SSH is also available (/account/ssh-keys); see Repositories.

Commits whose message names an issue key, such as DEMO-1: fix typo, are attached to that issue automatically (smart commits).

4. Create an issue

  1. Open /p/DEMO/issues/new or use New issue in the top bar.
  2. Enter a title and a Markdown description. Choose a type (task, bug, feature, story, epic), priority, assignee and labels.
  3. Save. You are on DEMO-1. Change the status from the issue page, or drag its card on the project's board.

Mention the key in a commit (DEMO-1: ...) and the commit shows up in the issue's Development panel. Read Issues and workflows and Boards and sprints next.

5. Run your first CI pipeline

CI needs Docker reachable from the GitBench process. In the dotnet run setup that is simply Docker running on your machine; Ci:Enabled is true by default there. Add a file named .gitbench-ci.yml at the root of the repository:

image: alpine:3.20
jobs:
  hello:
    steps:
      - name: Say hello
        run: echo "Hello from CI"
  check:
    needs: [hello]
    steps:
      - name: List files
        run: ls -la /workspace

Commit and push it:

git add .gitbench-ci.yml
git commit -m "Add CI"
git push

Open /p/DEMO/repos/hello/pipelines. A pipeline appears as Queued, then Running, then Passed. Click it to see each job and tail the step logs. Every job gets a fresh copy of the commit mounted at /workspace, and every step runs in its own container.

You can also start one by hand with Run pipeline on the Pipelines tab (Developer or higher). If the pipeline ends in Error with "Docker is not available on the server", see the troubleshooting entry. The full file format is in CI pipelines.
