Slack and Microsoft Teams

Post issue, pull request, pipeline and release updates to Slack or Teams channels, and (with a Slack app) use the /gitbench command, link previews and direct messages.

There are two layers, and you can use either one alone:

  • Channel integrations are created per project or per group. They need only an incoming webhook URL (Slack or Teams) or a Slack bot token. No server configuration is required.
  • The Slack app (server-wide, optional) adds the /gitbench slash command, link previews (unfurls) and Slack direct messages. It needs Slack:SigningSecret and, for previews and DMs, Slack:BotToken.

Create a channel integration

Needs the Maintainer role in the project, or Owner of the group for a group integration.

  1. Open Project, Settings, Slack & Microsoft Teams (/p/{KEY}/settings/integrations). For a group, open the group's Integrations tab.
  2. Choose Slack or Teams, give it a name, and pick a mode (below).
  3. Tick the events to announce and set optional filters.
  4. Save, then press Send test message. Test messages share the webhook ping limit (5 per minute per user).

A project or group can have at most 20 chat integrations. URLs and tokens are encrypted at rest (ASP.NET Core Data Protection, like webhook secrets) and never shown again; the page only shows a hint such as "••••••••3f9a". On edit, leaving a secret field blank keeps the stored one. An integration cannot change between Slack and Teams, so add a new one instead.

Modes: webhook or bot token

ModeYou provideNotes
Slack incoming webhookA https://hooks.slack.com/services/... URLPosts to the channel the webhook was created for. You can give a separate webhook URL per event group to send groups elsewhere.
Slack bot tokenA bot token (xoxb-...) and a default channel such as #dev or a channel idUses Slack's chat.postMessage. Each event group can post to its own channel. The bot must be invited to those channels.
Teams webhookA Teams incoming webhook (...webhook.office.com) or a Workflows / Power Automate URLAccepted hosts: *.webhook.office.com, *.logic.azure.com, *.api.powerplatform.com, *.powerautomate.com. Separate URLs per event group are possible.

Webhook URLs must be https, without credentials, on an allowed host. For a proxy or another host, add it to ChatIntegrations:AllowedHosts (see configuration). Only the scheme and host of an incoming webhook URL are stored in plain text, because the path is the secret.

Group integrations and opt-out

An integration created on a group announces the events of every project in that group and its subgroups, managed by the group's Owners. A project sees them under From the group on its integrations page, and a Maintainer can switch one to Opted out for that project without touching the group. Opt-outs are audited as chat_integration.opted_out and chat_integration.opted_in.

Message formats

  • Slack: Block Kit blocks inside a colour-coded attachment (green good, red failure, yellow warning, blue info, grey neutral), with a plain-text fallback. All user text is escaped, so <!channel> or <@U123> in an issue title cannot ping anybody.
  • Teams: an Adaptive Card (v1.4). User content is placed in text runs that Teams shows literally, with no Markdown or HTML. Cards are trimmed to stay under Teams' size limit.
  • Each message has a title linking to GitBench, an actor, a context line, up to 10 short fields and an excerpt of up to 1,500 characters.
  • Delivery uses a 10 second timeout, up to 3 retries, no redirects and the webhook SSRF checks. The integration is switched off after 20 failures in a row, and the delivery log shows the last 25 deliveries with Redeliver. See webhook delivery.

Set up the Slack app

Do this once per server if you want slash commands, link previews or DMs. Channel integrations do not need it.

  1. In api.slack.com/apps, create an app for your workspace.
  2. Copy the Signing Secret (Basic Information) and, for previews and DMs, the Bot User OAuth Token (xoxb-...) after installing the app.
  3. Give them to GitBench through the environment or user-secrets, never a committed file: 
    # production
Slack__SigningSecret=<signing secret>
Slack__BotToken=<xoxb token>
Slack__TeamId=T0123ABCD      # optional: accept only this workspace

# development
dotnet user-secrets set "Slack:SigningSecret" "<signing secret>"
  4. Set the request URLs in the Slack app (use your public GitBench address, which should match PublicBaseUrl):
Slack app screenURL
Slash Commands, command /gitbench, Request URLhttps://gitbench.example.com/integrations/slack/commands
Interactivity & Shortcuts, Request URL (the "Assign to me" button)https://gitbench.example.com/integrations/slack/interactivity
Event Subscriptions, Request URL; subscribe to the bot event link_shared, and add your GitBench domain under App unfurl domainshttps://gitbench.example.com/integrations/slack/events

Slack must be able to reach these URLs from the internet. The app also needs the matching Slack permissions for what you use (commands, posting messages, reading and writing link unfurls); Slack's own documentation lists the exact scope names.

Slack:* and ChatIntegrations:* settings

KeyDefaultEffect
Slack:SigningSecretnoneRequired for the Slack app. Without it the three /integrations/slack/* endpoints answer 404. Every request must carry a valid signature.
Slack:BotTokennoneNeeded for link previews and Slack DMs. Optional otherwise.
Slack:TeamIdnoneIf set, only requests from this workspace id are accepted.
Slack:TimestampToleranceSeconds300Replay window for X-Slack-Request-Timestamp (never less than 30). Accepted signatures are also remembered for the window, so a captured request cannot be replayed.
Slack:ApiBaseUrlhttps://slack.com/api/Slack Web API base URL (change only for tests or a proxy).
ChatIntegrations:AllowedHostsemptyExtra hosts integrations may post to besides Slack's and Teams' own. A leading dot (.example.com) matches subdomains.

Signatures use Slack's v0 scheme: v0= plus the hex HMAC-SHA256 of v0:{timestamp}:{body}. Request bodies over 64 KB are refused. Invalid requests get 401 and a warning in the server log.

Slash commands and account linking

Slash commands run as the GitBench user linked to the Slack user, so normal roles apply. Replies are visible only to the person who ran the command.

CommandDoes
/gitbench issue KEY-12 (or show)Shows an issue card, with Assign to me (Developer or higher) and Open in GitBench buttons
/gitbench create KEY Title of the issue (or new)Creates a task (title up to 200 characters; needs permission to create issues)
/gitbench search words (or find)Searches issues and pull requests (up to 8 results of each)
/gitbench link / unlinkConnect or disconnect your GitBench account
/gitbench or helpLists the commands

The account-link flow

  1. Run any command, or /gitbench link. If you are not linked, Slack replies with a Link GitBench account button.
  2. The button opens /integrations/slack/link?t=... in GitBench. Sign in and confirm.
  3. The link token is single use and expires after 10 minutes. A Slack account links to one GitBench account at a time.
  4. Unlink from Slack with /gitbench unlink, or from GitBench under your notification preferences. Linking and unlinking are audited as chat.slack_linked and chat.slack_unlinked.

Until a Slack user links, commands, buttons and previews do nothing for them except offer the link.

Link previews

With Slack:BotToken and the link_shared event, pasting an issue or pull request link from your GitBench address into Slack shows a card. The card is built as the linked user, so someone who cannot see the issue gets no preview. Unlinked users are offered the link flow. Only links on the GitBench host are handled (up to 10 per message).

Slack direct messages

With a bot token, each linked user can switch on Also send my notifications as Slack direct messages in their notification preferences. GitBench sends the notification as a DM from the app, checking every 30 seconds, one attempt per notification. DMs are a convenience next to the in-app notification, not the record. Without a bot token, or for users who have not linked Slack, pending DMs are dropped so no backlog builds up.

Troubleshooting

SymptomCheck
Slack says the slash command failed or the request URL is invalidThe signing secret is wrong or missing (the endpoints answer 404 without one, 401 with a bad signature). Check the server log for "Rejected a Slack request". Your server's clock must be accurate, within the tolerance.
"This GitBench server isn't connected to your Slack workspace"Slack:TeamId is set and does not match your workspace.
Test message works but real events do not appearThe event is not ticked, a branch, label or priority filter excludes it, or a mention has no matching user. Check the delivery log.
Integration shows "Disabled after 20 failures"Fix the cause (revoked webhook, bot not in the channel), then tick Active again to reset the counter.
"Use a Slack incoming webhook URL" or "Use a Teams incoming webhook"The host is not allowed. Use the provider's URL, or add a proxy host to ChatIntegrations:AllowedHosts.
"URL or token can't be decrypted"The Data Protection keys changed (for example after a rebuild without persisted keys). Enter the URL or token again.
No link previewsNo Slack:BotToken, the link_shared event or unfurl domain is not configured, or the person has not linked their account.
