Explore, search and keyboard shortcuts

Find projects you can see, star the ones you use, read what people have been working on, search everything from one box and move around without the mouse.

Everything on this page is filtered by what you are allowed to see. Nothing from a project you cannot view appears in Explore, search results or on anyone's profile; see Roles, groups and permissions.

Explore

Explore (/explore, in the sidebar) lists every project you can view, with its visibility, open issues, repositories, star count and last activity (the newest issue update, pull request update or push).

ControlWhat it does
Tabs: All, Starred, MineEverything you can view, projects you starred, or projects you are a member of
FilterMatches the key, name or description
SortBy name, recently active or most stars

Starring projects

The star button on each Explore row, and the one next to the project name in the sidebar on any project page, stars or unstars the project and shows its count. Starred projects come first in the sidebar's Projects list, marked with a star. Anyone who can view a project can star it, once per person and project. If you lose access to a starred project the star stays but is never shown.

API: PUT and DELETE /api/v1/projects/{key}/star return { project, starred, stars }, and GET /api/v1/user/starred lists your starred projects.

User profiles

A profile is at /u/{username} (case-insensitive). Names of authors, commenters, assignees and activity actors on issues, pull requests and feeds link to it.

  • Header: avatar, display name, @username, the date they joined, and the projects they belong to that you can see.
  • Activity feed: issues opened and closed (a move into a Done-category status), issue comments, pull requests opened and merged, pull request comments and pushes. Pushes are recorded per branch or tag that moved, with the number of new commits (capped at 100); pushes made before the feature existed are not in the feed.
  • Contribution calendar: a heatmap of the last 52 weeks. A day counts the feed events plus one per pushed commit; hover a day for its count. It follows the light and dark theme and scrolls sideways on narrow screens.
  • The home dashboard's "Activity from your projects" uses the same feed across every project you can see.

API: GET /api/v1/users/{username} returns the profile, the visible projects with roles and the latest 30 activity items you can see.

Global search

The search box

The app bar box (Search or jump to) is focused by pressing /. After a short pause it suggests the top three issues, pull requests, projects and users. If what you typed is an issue key such as WEB-12 and that issue is visible to you, it is the first suggestion, so Enter jumps straight to it. Otherwise the first entry is "Search for ...", and Enter opens the results page.

The results page

/search?q=... groups results into tabs, each with its total. Add &type= to link to one tab: issues, pull-requests, projects, users, wiki or code.

TabMatches against
IssuesKey, title and description
Pull requestsTitle and description
ProjectsKey, name and description
UsersUsername and display name
WikiPage title, path and content, with a short excerpt around the match
CodeFile contents (see below)

Syntax and limits

Global search has no operators. Whatever you type is one plain-text phrase:

  • Substring match, case-insensitive for ASCII. It is a database LIKE search with no full-text index. The characters %, _ and \ in your query are matched literally, so searching for 100% works as typed.
  • Issue keys of the form letters-then-digits, like WEB-12, redirect straight to a visible issue. A key that matches nothing falls back to the normal text search.
  • Queries are cut to 200 characters. Each tab lists the most recently updated matches.
  • Code is a separate tab because it runs git grep. It searches the default branch of each visible, non-archived repository as plain, case-insensitive text, with caps of 25 repositories, 20 matches per repository and 100 matches in all. For regular expressions and other branches use a repository's own code search (Code browsing and tools).

For structured issue queries (project = WEB AND status in ("In Progress", Blocked) AND assignee = currentUser()), use the issue list's advanced search. See Fields, filters and search.

API: GET /api/v1/search?q=...&type=... where type is issues, pull_requests, projects, users or code. Without type, every type except code is searched; code is only searched when asked for. perPage (maximum 100) caps each group, and jumpUrl is set when the query is a visible issue key.

curl -H "Authorization: Bearer $BYTEBENCH_TOKEN" \
  "https://bytebench.example.com/api/v1/search?q=WEB-12"
curl -H "Authorization: Bearer $BYTEBENCH_TOKEN" \
  "https://bytebench.example.com/api/v1/search?q=retry%20policy&type=code"

Keyboard shortcuts

Press ? anywhere to open the shortcut help. Shortcuts are single keys, and "g" shortcuts are two keys pressed one after the other (press g, then the second key within about a second).

"In a project" shortcuts use the project in the current address (/p/WEB/...), so they do nothing on pages outside a project. j and k start at the first or last row when nothing is selected. Enter opens the selection only when focus is on the page itself, not on a button or link. e and a work when the issue page shows those buttons (assigning to yourself needs permission to assign, as for the button).

When shortcuts are ignored

  • While you type in a text field, text area, drop-down or editor, and while a menu from a form control is open.
  • While a dialog is open.
  • With Ctrl, Cmd or Alt held, so browser and system shortcuts keep working.
  • When you turned them off.

Turning shortcuts off

The switch at the top of the ? dialog ("Keyboard shortcuts on/off in this browser") turns them off. The choice is stored in this browser's local storage, not in your account, so it applies per browser and survives sign-out. Screen-reader and voice-control users who find single-key shortcuts get in the way should switch them off.

The web editor has its own editor shortcuts; see Web editor and AI assistant.
