Glossary

Plain-language definitions of the terms used throughout ByteBench and its documentation.

A B C D E F G H I J K L M N O P R S T U V W

A

Access token
A personal token (prefix gbp_) you create on your profile with scopes such as read_repository, write_repository or API scopes. It replaces your password for Git over HTTP and the REST API. It is shown once; only its hash is stored. More.
Archived repository
A repository that refuses pushes. It stays readable.
Artifact (CI)
Files a CI job saves for later jobs or for download, declared with artifacts in the CI file. Stored zipped under Ci:ArtifactsRoot. More.
Audit log
A record of security-relevant actions (sign-ins, permission changes, key additions, settings changes). Site admins read it at /admin/audit. Kept for Audit:RetentionDays. More.
Automation rule
A trigger, optional conditions and actions that ByteBench runs for you, executed by an automation bot. More.

B

Backlog
The ordered list of issues not yet in a sprint. More.
Backup archive
A single bytebench-backup-(time).tar.gz file holding the database, repositories, files and keys, with a manifest and a .sha256 file. More.
Bare repository
A Git repository without a working copy. ByteBench stores every repository as one under Git:RepositoryRoot.
Board
A Kanban or Scrum view of a project's issues in columns. A project can have several. More.
Bootstrap admin
A user listed in Bootstrap:AdminUsers who is made a site admin at start-up. More.
Branch protection
Rules for matching branches: required reviews, required checks, no force pushes, optional merge queue. More.

C

Cache (CI)
Files kept between pipeline runs, such as package downloads, to speed up jobs. Limited per cache and per repository. More.
CI (continuous integration)
Running builds and tests automatically on every push or pull request. ByteBench runs jobs in Docker containers from a .bytebench-ci.yml file. More.
Circuit
The live connection between a browser and the Blazor server. Pages are interactive while the circuit is open.
Claude Code
Anthropic's command-line coding agent. ByteBench can run it on the server as a backend for the web editor assistant and AI review. More.
Code owners
A file mapping paths to people or teams who are automatically asked to review changes to them. More.
Component
A part of a project (for example Backend or UI) that issues can be assigned to. More.
Content root
The folder containing the application files. Default data folders (repos, attachments and so on) are created beneath it when running from source. More.
Content Security Policy (CSP)
A browser header that limits where scripts, styles and workers may load from. ByteBench sends one on HTML pages. More.
Cycle time
How long an issue takes from started to done. A delivery report metric. More.

D

Dashboard
A page of gadgets showing issues, sprints and metrics. Every user has a home dashboard and can pin a personal one. More.
Data Protection key ring
The keys ASP.NET Core uses to sign cookies and encrypt stored secrets. Lives in DataProtection:KeysPath. Back it up. More.
Deploy approval
A rule that a deployment to an environment must be approved by named people before it runs. More.
Deploy freeze
A time window in which deployments to an environment are blocked. More.
Deploy key
An SSH key attached to one repository for servers or CI. Read-only unless write access is ticked. More.
Deployment
A recorded release of a commit to an environment, usually created by a CI job with an environment. More.
Developer
Project role above Viewer: can edit issues, comment, push code, open and review pull requests, publish packages and toggle feature flags. More.
DORA metrics
Deployment frequency, lead time for changes, change failure rate and time to restore: four measures of delivery performance. More.
Draft pull request
A pull request marked not ready for review or merge. More.

E

Environment
A named deployment target such as staging or production, with its own history, approvals and variables. More.
Epic
A large issue that groups other issues, shown on the roadmap. More.

F

Feature flag
A switch evaluated by your application at runtime, with values per environment, targeting rules and percentage rollouts. More.
Fingerprint (finding)
A stable identity of a security finding, so triage decisions survive rescans. More.
Fingerprint (SSH key)
The SHA256: hash of a public key, shown in the key list and as ssh-keygen -lf prints it.
Fork
A personal copy of a repository from which you can open pull requests to the original. More.

G

Gadget
A single widget on a dashboard, such as an issue list or a burndown chart. More.
Git LFS
Git Large File Storage: keeps big files outside the repository history. ByteBench stores objects under Lfs:Root. More.
GQL
ByteBench Query Language, the search syntax for issues. More.
Group
A namespace that owns projects and subgroups, with members whose roles are inherited by everything below it. Nests up to four levels. More.
Group label / milestone
A label or milestone defined on a group and inherited by every project below it. More.

H

Health check
The /health/live and /health/ready endpoints used by Docker and load balancers. More.
HSTS
HTTP Strict Transport Security: a header telling browsers to use HTTPS only. Sent on HTTPS responses outside Development. More.

I

Internal (visibility)
Visible to every signed-in user, who count as Viewers. The other option is Private. More.
Issue
A unit of tracked work, numbered per project (WEB-12), with type, status, priority, assignee and so on. More.
Issue key
The identifier of an issue: project key, a dash and a number, such as WEB-12. Writing it in a commit message links the commit to the issue. More.

J

Job (CI)
A named group of steps in a pipeline that runs in one container image. Jobs can depend on each other with needs. More.

K

Key (project)
The short upper-case identifier of a project, 2 to 10 letters or digits starting with a letter. More.

L

LDAP
A directory protocol (Active Directory, OpenLDAP). ByteBench can authenticate users against it and map directory groups to ByteBench groups. More.

M

Maintainer
Project role that can also merge pull requests and manage repositories, labels, milestones, sprints, flags and packages. More.
Member
A user with a role on a project or group. More.
Merge queue
A per-branch queue that tests and merges approved pull requests in order, in batches, so the target branch stays green. More.
Merge strategy
How a pull request is merged: merge commit, squash or rebase, as allowed by the repository. More.
Migration
A versioned database schema change. ByteBench applies pending migrations automatically at start-up. More.
Milestone
A target with an optional date that issues are attached to, with progress tracking. More.
Mirror
A repository kept in sync with another one: pull mirrors fetch from a remote, push mirrors push to one. More.

N

Night Owl
An open-source security scanner. ByteBench ingests its JSON and SARIF reports from CI into findings. More.
Notification
An in-app (and optionally email or chat) message about something you are involved in. More.

O

OAuth / OIDC
Protocols for single sign-on. ByteBench supports OpenID Connect providers and GitHub's OAuth. More.
OCI registry
The container image registry built into each project, served under /v2. More.
Owner
The highest project role: also manages members, settings and visibility, and can delete the project. More.

P

Pages
Static websites published from a CI job and served by ByteBench. More.
Pipeline
One run of a repository's CI file for a commit. Statuses: Queued, Running, Passed, Failed, Canceled, Error, Manual. More.
Postgres
PostgreSQL 14 or newer, the optional alternative to SQLite. More.
Private (visibility)
Visible only to members. More.
Project
The unit of work and access: has a key, members, issues and repositories. More.
Protected tag
A tag rule that restricts who may create, move or delete matching tags. More.
Pull request
A proposal to merge one branch into another, with review, discussion and checks. More.

R

Rate limit
A cap on requests per time window. Over it you get HTTP 429 with Retry-After. More.
Release
A tagged version of a repository with notes and downloadable assets. More.
Repository
A Git repository inside a project. A project can have several, each with a slug. More.
Reverse proxy
A web server (Caddy, nginx) in front of ByteBench that terminates TLS and forwards requests. More.
Requester
A person who filed a service desk request. Just a name and an email address, never an account; they see their request on a private tracking page. More.
Review site
A temporary Pages site published for a non-default branch. More.
Roadmap
A timeline of epics per project or group. More.
Role
Viewer, Developer, Maintainer or Owner: what a member may do. More.

S

SARIF
A standard JSON format for static analysis results, accepted from any scanner. More.
Scope (token)
A permission attached to an access token, for example read_repository or write_repository. More.
Segment (feature flag)
A named list of user ids that flag rules can target. More.
SDK key
A key per feature-flag environment that your application uses to fetch flag values. More.
Seed data
The demo users, projects and issues created in an empty Development database. Their shared password is the constant SeedData.DemoPassword. More.
Service desk
A mailbox and public form that turn messages from people without accounts into issues. More.
Speculative commit
The commit a merge queue builds for a queued pull request: the target branch plus every pull request ahead of it, stored under refs/merge-queue/ and tested by a pipeline. More.
Site admin
A user with the admin flag: treated as Owner of every project and able to use /admin pages. More.
Slug
The URL name of a repository inside a project, or a path segment of a group. More.
Smart commit
A commit message that mentions an issue key, which links the commit to the issue after a push. More.
Snippet
A small shareable piece of code or text with its own visibility. More.
Sprint
A time-boxed set of issues in Scrum, with start, complete, burndown and velocity. More.
SSO
Single sign-on: signing in with an external identity provider. More.
Status check
A result from CI, AI review or a security scan that can be required before a pull request merges. More.
Step (CI)
One command in a job, run in its own container with sh -e -c. More.
Story points
A relative estimate of effort on an issue. More.
Star
A bookmark on a project. Starred projects come first in the sidebar and can be listed on Explore. More.
Subgroup
A group inside another group. More.

T

Triage (AI)
AI suggestions for labels, component, priority and possible duplicates of a new issue. More.
Triage (security)
Deciding what to do with a finding: confirm, dismiss as false positive or accepted risk, or reopen. More.

U

User-secrets
A .NET development store for configuration secrets outside the source tree. More.

V

Viewer
The lowest project role: read-only. More.

W

Webhook
An HTTP callback ByteBench sends when something happens (push, issue, pull request, pipeline and more), signed and retried. More.
Wiki
A Markdown knowledge base per project. More.
Workbench
The company ERP where time and cost are recorded. ByteBench links to its timesheets but does not track time itself. More.
Workflow
The set of statuses and allowed transitions for a project's issues. More.
Workspace (CI)
The folder with a commit's files mounted at /workspace in every job container. More.
Workspace (web editor)
Your private, uncommitted set of edits to a repository branch in the web editor. More.
