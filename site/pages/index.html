GitBench

One self-hosted place for planning work, hosting Git repositories, reviewing code, running CI and shipping releases: a Jira plus GitLab or Bitbucket style platform written in C# with Blazor on .NET 10.

What GitBench is

Most teams stitch together an issue tracker, a Git host, a CI server, a package registry and a chat bot. GitBench puts these in a single ASP.NET Core application with one database and a few folders on disk, so you can run the whole thing on one machine with docker compose up.

  • Plan. Projects with issues, workflows, Kanban and Scrum boards, sprints, a roadmap, custom fields, a query language (GQL), dashboards, automation rules and a service desk.
  • Code. Repositories served over Git HTTP and a built-in SSH server, pull requests with reviews and code owners, branch protection, a merge queue, forks, mirroring and Git LFS.
  • Build and ship. CI pipelines that run in Docker, environments with deploy approvals, a NuGet, npm and container registry, static sites (Pages), feature flags and security scanning with Night Owl.
  • Connect. A REST API, webhooks, Slack and Microsoft Teams, email notifications, single sign-on (OIDC and OAuth) and LDAP.
  • Assist. Optional AI features that use Claude: pull request review, issue triage and an assistant in the web editor. They are off until you give the server an API key or install Claude Code.
GitBench is meant to run as one instance. Its background queues (CI, webhooks, email, AI review) live inside the process, so do not run several replicas against the same data.

What is where

This is a map of the main places in the GitBench web interface. {KEY} is a project key such as WEB and {slug} is a repository name.

AddressWhat you find there
/Your dashboard: assigned work, projects and activity
/projects/new, /groups/newCreate a project or a group
/p/{KEY}/issuesThe project's issues (and /p/{KEY}/issues/new to file one)
/p/{KEY}/reposRepositories inside the project
/p/{KEY}/repos/{slug}/pipelinesCI pipelines of a repository
/p/{KEY}/repos/{slug}/pull-requestsPull requests of a repository
/p/{KEY}/settingsProject settings (name, visibility, members)
/g/{path}A group or subgroup
/git/{KEY}/{slug}.gitThe Git HTTP clone address
/api/v1 and /developers/apiThe REST API and its documentation page
/account/profile, /account/ssh-keysYour profile, access tokens and SSH keys
/admin/users, /admin/audit, /admin/system, /admin/backupsSite administration (site admins only)
/admin/authentication, /admin/ai, /admin/packagesMore site admin pages: SSO and LDAP status, AI status, registry storage
/health/live, /health/readyHealth checks for load balancers and Docker
