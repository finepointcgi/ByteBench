Desktop app

The ByteBench desktop app opens any ByteBench server (yours or a team's) in its own window, so you can work with issues, boards, pull requests, code, CI, workspaces and test runs like in a native application. It shows the server's normal web interface; nothing is installed on the server.

Install

Installers for macOS (dmg or zip, Apple Silicon and Intel), Windows (installer) and Linux (AppImage and deb) are attached to the desktop-v* releases of the project on GitHub. Release builds are unsigned unless the maintainers added signing certificates, so macOS and Windows may show a warning on first start. Packaged builds update themselves from GitHub releases.

To run it from source: cd desktop && npm ci && npm start (Node 22 or later).

Servers

On first start the app asks for the address of a server, for example https://bytebench.example.com or localhost:5108. You can save several servers and switch with File → Switch Server (Cmd/Ctrl+K), the Servers menu (Cmd/Ctrl+1…9) or the tray menu. Each server has its own sign-in; removing a server deletes its cookies and cache on your computer.

  • Plain http is accepted without a prompt for localhost, private networks and local-only names; for any other host you must confirm it.
  • Self-signed certificate: tick the option for that server. When the connection fails, the error page shows the certificate's SHA-256 fingerprint; Review and trust certificate asks you to confirm, then pins exactly that certificate. A different certificate later is refused.
  • Single sign-on: if your server signs in through another website, add that address (https only) under Trusted sign-in addresses for the server. Otherwise links to other sites open in your default browser.
  • The app checks GET /api/v1/server-info when it opens a server. A server without it still works but has no notifications; a server newer than the app shows a hint to update the app. If the server cannot be reached the app shows an error page with Try again.

Notifications and badge

The app checks each saved server's own notifications about every 30 seconds (and less often while a server is down), using your signed-in session or, if you saved one, a personal access token with read_api. New unread notifications become operating system notifications; clicking one opens the item. The unread total appears as the dock badge (macOS, Linux), a taskbar overlay (Windows) and in the tray or menu-bar item. Turn them off under Servers → Desktop Notifications. Tokens are stored encrypted with the operating system keychain, and not at all if no keychain exists.

On Windows and Linux, closing the window keeps the app running in the tray so notifications continue; quit from the tray menu.

bytebench:// links

bytebench://open?server=<id|name|host>&path=/p/KEY/issues/12 opens a page of a server you already added. The server is matched by id, name or host name. The path must be a path on that server. A link can never add a server or open another site; links that do not match are refused with a message. Installed builds register the link scheme; a build run from source does not.

Clone with ByteBench

File → Clone This Repository (Cmd/Ctrl+Shift+C) on a repository page asks for a folder, runs git clone for the repository's HTTP clone address, and opens the new folder in VS Code (or another graphical editor named in $VISUAL or $EDITOR), otherwise shows it in your file manager. Git must be installed. For private repositories save a token for the server; it is passed to Git through its environment and never appears on a command line.

Workspaces

Go → Workspaces opens your workspaces. The IDE and previews are served from ide-* and p<port>-* addresses under the server's workspace domain; the app opens those of the same server in a window of their own that shares your session. Copy and paste works in the IDE.

Security

  • Pages run in sandboxed renderers with context isolation and no Node.js; the only bridge offered to a server page can ask to clone a repository, and a native folder picker always appears.
  • Only the server's own address stays in the app. Other web links open in your default browser, and file, script and data addresses are blocked. Pop-ups never open windows of their own.
  • Only notifications and the clipboard may be used by pages; camera, microphone, location and other permissions are denied.
  • Every server has its own cookie store. The saved server list contains no secrets.

What the server provides

Two small API additions: GET /api/v1/server-info (no sign-in: name, version, API version, capabilities and the workspace domain) and your own notifications, GET /api/v1/notifications (filters unread=true, afterId, limit; also returns unreadCount) and POST /api/v1/notifications/{id}/read.

Limits

  • Browser push notifications do not exist in the app; the notification check described above replaces them.
  • Updates on macOS need a signed build.
