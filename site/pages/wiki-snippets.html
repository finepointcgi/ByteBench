Wiki and snippets

Every project has a Markdown wiki that is also a Git repository, and anyone can share small pieces of code or text as snippets, personal or per project.

Project wiki

Open Wiki in the project sidebar (/p/{KEY}/wiki, or /p/{KEY}/wiki/{path} for a page). Behind the scenes the wiki is a bare Git repository at {Git:RepositoryRoot}/{KEY}/{key}.wiki.git, created on first use, with one Markdown file per page on main. That gives you history, revert and clone for free.

Pages and the sidebar

  • Pages are files named {path}.md. A / in the path makes folders (guides/Getting-started); spaces become -; the page title is the last path segment.
  • home is the landing page.
  • The sidebar shows the generated page tree. Create a page called _sidebar (Customise sidebar) to replace the tree with your own Markdown navigation.

Creating and editing

  1. Click New page and enter a path, or follow a red link to a page that does not exist yet.
  2. The editor (?action=edit) is the Markdown editor with a wiki-aware preview, a page path field (change it to rename or move the page), an optional commit message and Upload image.
  3. Save. Each save, rename, delete or revert is a Git commit authored by you.

Edit conflicts. The editor remembers the version it opened. If the page changed (or was deleted) since then, nothing is written; you see the current version and can choose Save mine anyway or Discard mine, edit theirs. Creating or moving a page onto an existing path is also a conflict. The check runs under the repository lock, so two writers cannot both win.

History

?action=history lists the commits that touched the page. For each: View (?rev=), Changes (the diff), Compare with current, and Revert to this, which makes a new commit rather than rewriting history.

Markdown features

Wiki pages, issues, comments, README files and snippet descriptions all use the same Markdown (the Markdig "advanced" feature set). You can use:

  • headings, emphasis, lists, block quotes, links and images
  • tables, task lists (- [ ]), footnotes, definition lists, abbreviations and automatic links
  • fenced code blocks with a language for syntax highlighting (```yaml)
  • @username mentions (highlighted, and they notify in issues and pull requests) with autocomplete in the editor
  • Raw HTML is escaped, not rendered, for security.

Wiki-specific syntax (processed by the wiki renderer):

WriteResult
[[Page Name]]Link to a page. Resolved next to the current page first, then from the root, then by unique title
[[guides/Setup|the setup guide]]Link with your own label
[text](other-page), ![](uploads/pic.png)Relative links and images resolve against the page's folder (uploads/... from the root)
WEB-12This project's issue keys link to the issue, except inside code or existing links

Missing pages show in red and open the editor. Links with a scheme other than http, https or mailto are neutralised.

Images

Use Upload image in the editor. Images are committed to uploads/ in the wiki repository (PNG, JPEG, GIF or WebP, checked by file signature, at most 10 MB) and served from /wiki-files/{KEY}/{path} with nosniff and a sandbox policy. Anything that is not one of those image types is sent as a download.

Cloning the wiki

git clone https://bytebench.example.com/git/WEB/wiki.git
git clone ssh://git@bytebench.example.com:2222/WEB/wiki.git

KEY/wiki.git and KEY/{key}.wiki.git both work, over HTTP and SSH. Authentication is the same as for code repositories (Repositories). Branch protection, deploy keys and code push listeners do not apply to wikis; after a push the search index is rebuilt. The repository slugs wiki and *.wiki are reserved so a code repository cannot clash.

Permissions and turning it off

ActionRole
Read pages, history, searchViewer (ViewProject)
Create, edit, rename, delete, revert, upload, push over GitDeveloper (EditIssues)
Turn the wiki on or off for the projectOwner (ManageProjectSettings), in Project settings, Wiki

The wiki is on by default. Turning it off hides the pages, the Git remote (it answers 404) and search hits, but deletes nothing; turn it on again to get everything back.

Search

Wiki pages (title, path and text) are indexed after every save and push. The global search has a Wiki group and tab (type=wiki); see Fields, filters and search.

Snippets

Snippets are small pasted pieces of code or text, like gists. A snippet has a title, an optional Markdown description, a visibility and 1 to 10 files (512 KB each, 1 MB in total). Files are highlighted by extension.

PageShows
/snippetsYour snippets (Snippets in the main sidebar)
/snippets/explorePublic snippets from everyone
/p/{KEY}/snippetsA project's snippets (Snippets in the project sidebar)
/snippets/new[?project=KEY]Create (personal, or for a project)
/snippets/{id}[?rev=n], /snippets/{id}/editView (with a revision picker) and edit

Visibility and sharing

VisibilityWho can see itAvailable for
PrivateOnly the authorpersonal and project snippets
ProjectEveryone who can view the projectproject snippets only
PublicEvery signed-in userpersonal snippets only

"Public" means every signed-in user of this ByteBench server; there is no anonymous access. Site admins see everything. To share, copy the snippet's URL, or use the raw and embed links below.

  • Raw: /snippets/{id}/raw/{file} (add ?rev= for an older revision, ?download=1 to download). Always text/plain; charset=utf-8 with nosniff and a sandbox policy.
  • Embed: /snippets/{id}/embed is a chrome-less read-only view. Embed on the snippet page copies an <iframe> tag. Embeds are allowed only from the same site (frame-ancestors 'self') and require sign-in, so they work on pages hosted on your own ByteBench domain for signed-in viewers.

Revisions and storage

Snippets live in the database, not in Git repositories. Every change to the files adds a revision holding a full copy, so the snippet page has a revision picker without a repository per snippet. Title, description and visibility change in place without a new revision.
