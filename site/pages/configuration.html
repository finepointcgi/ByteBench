Configuration reference

Every setting ByteBench reads, grouped by area, with its default, what it does and an example, plus how files, environment variables and user-secrets combine.

Where settings come from

ByteBench uses the standard ASP.NET Core configuration system. Later sources override earlier ones:

  1. appsettings.json (shipped defaults)
  2. appsettings.{Environment}.json: appsettings.Development.json or appsettings.Production.json
  3. user-secrets (only in the Development environment)
  4. environment variables
  5. command-line arguments

The environment is chosen by ASPNETCORE_ENVIRONMENT (Development with dotnet run --launch-profile http; Production in the Docker image). The shipped appsettings.json only sets Logging, AllowedHosts, Email, ServiceDesk and Ci; everything else uses the defaults in this page.

The double-underscore syntax for environment variables

A configuration key such as Ci:MaxConcurrentJobs is written Ci__MaxConcurrentJobs as an environment variable, because : is not allowed in variable names on most systems. Nesting adds more __; list items are numbered:

# Ci:MaxConcurrentJobs
Ci__MaxConcurrentJobs=4
# Email:Smtp:Password
Email__Smtp__Password=...
# ReverseProxy:KnownNetworks (a list)
ReverseProxy__KnownNetworks__0=172.16.0.0/12
ReverseProxy__KnownNetworks__1=10.0.0.0/8
# RateLimiting:Api:PermitLimit
RateLimiting__Api__PermitLimit=600

In docker-compose.yml put them under environment: (quote values: Ci__Enabled: "true"). Names are case-insensitive. Command-line form: dotnet run --launch-profile http -- --Email:Enabled=true.

User-secrets (development)

The project already has a UserSecretsId, so you can store keys and passwords outside the source tree without any setup:

dotnet user-secrets set "Ai:ApiKey" "<your key>"
dotnet user-secrets set "Email:Smtp:Password" "<password>"
dotnet user-secrets set "Slack:SigningSecret" "<secret>"
dotnet user-secrets list

User-secrets are only read in Development. In production use environment variables (or an env_file with mode 600, or Docker secrets). Keep secrets out of appsettings.json and out of the image.

ANTHROPIC_API_KEY

The AI features need a Claude API key. ByteBench uses Ai:ApiKey if set, otherwise the plain environment variable ANTHROPIC_API_KEY. The environment variable is the recommended way:

export ANTHROPIC_API_KEY=...        # then start ByteBench
# or in docker-compose.yml
ANTHROPIC_API_KEY: "${BYTEBENCH_AI_API_KEY}"

With no key and no Claude Code on the server, every AI feature hides itself. See AI overview and setup.
